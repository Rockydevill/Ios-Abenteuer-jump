How we review submitted games.

Manual approvalNo automatic publication

1. Submission completeness

We first check that all required details are present: game name, developer, version, minimum Android version, pricing model, descriptions, cover image, app logo, game file and required confirmations. APK, ZIP, HTML and HTM files are currently supported.

2. Technical file review

For APK files, where technically possible, we review package name, signature, minimum and target SDK, permissions, referenced domains, libraries and notable resources. ZIP, HTML and HTM files are reviewed for included files, scripts, external resources and network targets. File hashes and other static checks may also be used.

3. Functional review and installation artifact

A submitted APK is installed and launched in a suitable test environment where possible. We check basic usability, startup behavior, important menus and visible functionality. ZIP, HTML and HTM source packages remain private and are never delivered to players as developer archives. After technical review, the package processor must create and validate a controlled Android installation artifact. Only a successfully validated installation artifact may later be approved for release. If the process cannot produce a valid artifact, the game remains unpublished. Submitted HTML or HTM source code is not exposed publicly under the gamesbehinddoors.de origin.

4. Monetization and payment methods

We compare the declared pricing model with the visible and technically identifiable behavior of the game. We specifically look for shops, purchases, in-app purchases, subscriptions, passes and external payment links. PayPal is currently the only payment provider supported for purchases, in-app purchases, subscriptions and passes processed through Games Behind Doors. Google Play Billing, Klarna and other payment providers are not supported.

If a game is submitted as free but contains an undisclosed purchase or payment function, it is not published. The developer will normally receive a correction request and may either declare the monetization correctly and connect PayPal or submit a new build without the unsupported payment method. Repeated incorrect declarations may result in rejection.

5. PayPal readiness for monetized games

The 10% platform commission applies only to paid games and in-app purchases, subscriptions and passes processed through Games Behind Doors. For recurring subscriptions, it applies to each payment processed through the platform. Recurring payments are enabled only after PayPal grants the required partner capability to Games Behind Doors. Before publication, we verify that the monetization terms were accepted and that the developer's PayPal seller account is active and able to receive payments. A monetized offer is not published until these requirements are met.

6. Game privacy

The developer must state whether the game processes personal data, such as login data, analytics, advertising data, cloud data or payment data. If it does, a reachable privacy policy for the game must be provided before publication. These declarations are compared with functions visible during technical and functional review.

7. Content, rights and store presentation

We check submitted information for obvious violations of platform rules. Developers must hold the necessary rights to the game and submitted media. Cover image, app logo, description and screenshots are checked for obvious mismatches or misleading presentation.

8. Review outcome

A submission may be approved, kept under review, returned with a correction request or rejected. A correction request is appropriate when the game could in principle be published but details, privacy information, monetization or the submitted build need adjustment.

9. Updates

New game versions may be reviewed again. A previous approval does not mean later versions are published automatically. Changes to payment functions, privacy, permissions or external services must be declared again.

10. Limits of review

Manual, static and functional review can reduce risk but cannot guarantee complete freedom from bugs, absolute security, compatibility with every Android device or the absence of previously unknown malicious behavior. Games Behind Doors therefore describes a game as reviewed, not guaranteed safe.
